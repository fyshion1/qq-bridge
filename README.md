## 它到底做什么

```
QQ 网关（OneBot v11：**SnowLuma** 为首选；NapCat / Lagrange 等同类一样能接）
   │  ① 收到消息（白名单之外的**一律不理**）
   ▼
本项目（qq-bridge）
   ├─ ② 图片 / 表情包 / 视频 → 下载字节 → 交给大脑落盘（前端才显示得出来）
   │      视频还会请大脑抽 ≤4 帧 → 走视觉路，小糖人真的「看」得到
   ├─ ③ 语音 → 转文字（见下面「语音」一节的坦白）
   ├─ ④ 带上最近聊过的上下文 → 请大脑里这位小糖人说话（人格 / 记忆 / 密钥都在大脑）
   ▼
QQ  ◀── ⑤ 回话：文字（长文自动切条）/ 语音条 / 表情包 / 出件箱里的图片视频
小窝前端 ◀── ⑥ 同一轮对话各写一份：群聊 → 群聊会话，私聊 → 对应私聊
```

### 读取合并转发

收到 `forward` 段后，桥通过 SnowLuma 的只读 `get_forward_msg` 动作读取内部消息，保留原发送者、时间、顺序和嵌套结构。图片、表情包、视频、语音继续使用现有附件/抽帧/转写管道；视频必须由本机后端 ffmpeg 抽帧，仅帧图交给模型，原视频只保存在本地；文件和卡片暂显示类型占位符。

每个外层 QQ 消息共享上限：3 层、50 个节点、12,000 字符、10 张图片（含表情包）、1 个视频、4 条语音、6 次网关查询，读取阶段最多等 20 秒。达到上限、记录失效或网关失败时会写明原因，不让模型误以为已读全。该限制不等于整个会话的总 token 限制；图片和视频还受本体视觉预算控制。

白名单、管理命令和群聊回复条件先按外层消息判断。转发内的姓名、`@` 和 `/reset` 等作为引用正文，不继承发送者权限、不直接触发管理动作。转发中只出现 `@机器人` 不会使外层群消息自动回复；需要在外层消息中正常呼叫。

依据：[SnowLuma 官方 get_forward_msg 文档](https://snowluma.github.io/zh/docs/api/extended/get_forward_msg)，响应为 `data.messages` 的 OneBot 消息事件数组；优先传资源 `id`，没有资源标识时可用外层 `message_id`。已与本机 1.14.22 发行包实现核对。修改后重启 QQ 桥加载代码，网关无需升级。

离线验证：在本目录运行 `../../backend/.venv/Scripts/python.exe -X utf8 -m unittest discover -s tests -v`；包含正文/媒体入站、嵌套、循环、预算、超时、身份及群聊触发隔离。没有发送真实 QQ 消息或调用付费模型。

### 一个账号演一位角色，或跟随群聊成员

「这个号演谁」可以选具体角色，也可以选「群聊」。群聊模式由当前 `group_roster` 决定谁在场，一人分饰多角色，并跟随当前用户身份切换历史和已审核记忆。

**一份配置可以带好几个号**（大老大原话：「我 QQ 号一堆，可以每个都配一个」）：
`accounts` 里写几条就带几个号，每个号自己的人格 / 白名单 / 网关端口，互不干扰 ——
群聊里被 @ 时各回各的，不会互相抢话。哪个号演谁**在小窝前端切换**，改完下一轮生效不用重启。

```jsonc
"accounts": [
  { "name": "大号",  "self_id": 553350415, "persona": "dashiyin",
    "ws_url": "ws://127.0.0.1:3001/", "groups": [123456789], "private": [] },
  { "name": "小号",  "self_id": 111222333, "persona": "xiaoshiyin",
    "ws_url": "ws://127.0.0.1:3002/", "groups": [123456789], "private": [] }
]
```

`ws_url` 是**正向 WS**（默认走法）时每个号自己的网关地址；走反向 WS 就改成填
`listen_port`（3010、3011…）。留空 = 用顶层那个。

`accounts` 留空 = 单账号模式（用顶层 `onebot.*` / `persona.*` / `allow.*`）。
两种都行，其实这些**在小窝前端「⚙ 功能开关 → QQ 桥」里点几下更省事**（见下面「配置在哪改」）。

## 和参考项目（Derpyu520/qq-bridge）的不同

参考项目值得抄的地方我抄了（OneBot v11、SILK 交给网关、发送白名单、语音额度）；
**这几处故意不抄**，因为和「大脑 / 外设」这个架构打架：

| 事情 | 参考项目 | 本项目 | 为什么 |
|---|---|---|---|
| 图片视频存哪 | 自己在桥里落盘 + 自己起静态服务 | 交给大脑的附件管道（`/api/qq-bridge/attachments`） | 前端聊天记录只认那一套（缩略图 / 画廊 / 删消息级联）。桥自己另存一份，删消息时文件就漏了 |
| 视频抽帧 | 自己在桥里 ffmpeg | 交给大脑的 `/api/media/video/analyze` | 大脑已经写好且带 15 秒 / 50MB / 8 帧的安全线，重复实现只会两处不一致 |
| 语音合成 | 自己接 TTS + SILK 编码 | 交给大脑的 `/api/voice/tts`（edge 晓晓 / piper 华燕 等） | 音色是用户在**大脑**里定的；SILK 仍是网关做（我们只给绝对路径） |
| 人设 | 桥里带一份角色卡 | 只传 `character_id` | 人设只有「角色介绍」一个来源，复制就会漂移 |
| 密钥 | 桥里配 | 一行都不存 | 统一走大脑的 `/api/nest/features/qq_bridge/api-config` |

**和 B站那个项目同一套规矩**：通过 HTTP 调用本体接口，不 import 本体代码；会话及表情使用 `/api/qq-bridge/*`。

## 怎么跑

### 0. 先配大脑

小窝前端 → 「🧠 小窝大脑 API」→ 填全局默认（或给 QQ 桥单配一份）。
QQ 桥在注册表里声明了 `needs_vision: true`，所以**记得也配视觉路**（看图要用）。

### 1. 装 QQ 网关

本项目**不内置网关**，也不碰 QQ 协议。**推荐 SnowLuma**，理由写在下面。

#### 为什么是 SnowLuma

先说清楚：**换网关不用改本项目一行代码。** 桥只讲 OneBot v11（`send_private_msg` /
`get_login_info` / notice 事件那一套），谁按这个标准来都能接。所以这不是技术选型，
是「哪个装起来顺、资料多」。

选 SnowLuma 的理由：

1. **自带运行时、下载即用** —— 解压一份 90 多 MB 的目录，双击 `launcher.bat` 就起，
   不用先装一套 QQNT 再往里注入。
2. **协议层就是 NapCat** —— 它复用 NapCat 的 `OB11Protocol` / `BotAPI` / `EventParser`，
   所以字段全、报错也和 NapCat 一个语系，搜得到。
3. **自带 WebUI**（`127.0.0.1:5099`）—— token、WS 端口、「反向 WS 地址」都在网页上点，
   不用改文件、不用重启（`POST /api/config/:uin` 热重载）。

（本机以前装过 NapCat，也完全能用 —— 桥这边一个字段都不用改。）

#### SnowLuma 和 NapCat 是什么关系

不是竞品，是**同一层东西的两种包装**：

- **NapCatQQ** —— 上层协议端。挂在官方 NTQQ 客户端上，把客户端能力包成 OneBot 11。
  需要本机装 QQ 并保持登录，然后往进程里注入。
- **SnowLuma** —— 同一层，但是**独立协议端**（自带 Node 运行时，不依赖本机 QQNT），
  协议层**大量复用 NapCat** 的那几套代码。

**对这座桥来说，两者来的字节是一样的** —— 上层框架视角下根本分不出来。

> 本项目**不用 AstrBot / MaiBot / NoneBot 这类上层框架** —— 这座桥自己就是上层。
> 所以「生态 / 插件市场」那套考量在这里不适用，只要协议端把字段给全就行。

#### 装 + 连（SnowLuma 走法，本机正在用的）

1. 解压 SnowLuma（本机在 `D:\SnowLuma\`），双击 `launcher.bat`（或 `cmd //c "D:\SnowLuma\launcher.bat"`）。
2. 浏览器开 `http://127.0.0.1:5099` → 登录 → 同意 EULA/隐私 → 改掉初始密码。
3. 网关里**开 QQ 并登录**（要注入进程就按它的提示来），登录后在「进程」页能看到 UIN。
4. 每位 QQ 号在 `config/onebot_<uin>.json` 里各有一份配置，默认：
   - **WS 服务端**（就是我们要连的那个）`127.0.0.1:3001`
   - **HTTP 服务端** `3000`
   - `accessToken` —— **在 WebUI「配置 → 网络」里能看到**（默认会生成一串），
     复制出来填到本桥的 `onebot.access_token` 里，**两边一致**。

#### 走正向 WS（**默认，推荐**）

本桥**主动连**网关 —— 网关那边什么都不用配、不用重启。这正是本机跑通的走法：

```
ws://127.0.0.1:3001/          ← SnowLuma 第一个号的 WS 服务端端口
```

填在 **前端「💬 QQ 桥设置 → 接入方式 → 网关地址」**（对应 `onebot.ws_url`），
连接方式选「我连网关（正向）」。连上会打一行：

```
✅ 和 QQ 网关连上了，我是 芳月诗音（553350415）
```

**多号的话**——SnowLuma 是「一个 QQ 号一个 ws 服务端端口」，所以**每个号填自己的地址**
（第二个号就是 3002，以它的配置为准），在前端「谁在 QQ 上」那张表的「网关地址」一列逐行填。

#### 走反向 WS（网关连我）

反过来也行：把连接方式改成「网关连我（反向）」，本桥监听 **3010**
（`onebot.listen_port`，**故意不用 3001** —— 那是 SnowLuma 自己占的，撞上就是连不上），
然后在 SnowLuma 里加一条「反向 WS」指过来：

```
ws://127.0.0.1:3010/onebot/v11/ws
```

多号时每个号一个端口（3010、3011…），路径不变，前端那张表的「监听端口」填一样的。

### 2. 建配置

**其实不用建**——白名单 / 演谁 / 音色 / 表情包 / 小工具全都能在小窝前端
「⚙ 功能开关 → 💬 QQ 桥」里改（存大脑，桥每 30 秒读一次，改完立刻生效、不用重启）。
`config.json` 留着两个用途：**没起大脑时兜底**，和「我就要写死在文件里」。

真想用文件的话：

```bash
python -m qqbridge example          # 写出 config.example.json
cp config.example.json config.json  # 再改 config.json（它已被 .gitignore 挡住）
```

**至少要填两处，不然它谁都不理**：

```jsonc
{
  "allow": {
    "groups":  [123456789],   // 要接的群号（空 = 群里谁都不理）
    "private": [987654321]    // 要接的私聊 QQ 号（空 = 私聊谁都不理）
  },
  "persona": { "character_id": "dalaoda" },   // 这个号演谁（= 角色介绍里的 id）
  "owner":   { "qq": 987654321 }              // 管理员（不受白名单限制；留空 = 没有管理员）
}
```

**两个入口谁说了算**：`代码默认` → `config.json` → `前端设置`。**前端最高** ——
你在网页上点的那一下就是最后生效的那个。只在 `config.REMOTE_KEYS` 登记过的项能从前端改，
别的 key 一律忽略（免得「顺手改点别的」）。

### 3. 跑起来

**推荐在小窝前端点**：糖人小窝 → 💬 QQ 桥 → 「自检（不连 QQ）」先看一眼 →
「接上 QQ（常驻）」→ 日志就在旁边滚动（后端按 utf-8 读，中文不乱码）。

命令行也行（在**本目录下**）：

```bash
python -m qqbridge check      # 自检：大脑通不通、白名单空不空、模型配没配（不连 QQ）
python -m qqbridge whoami     # 这个号演谁 + 家里有哪些人
python -m qqbridge run        # 常驻
```

Windows 终端中文乱码就设 `PYTHONIOENCODING=utf-8`（在小窝前端点的话后端已经帮你设了）。

### 4. 不想装 QQ 也能先试

`tools/fake_onebot.py` 是个**假网关**：它连上桥、发一条消息、把桥的回复打出来。

```bash
python tools/fake_onebot.py                       # 私聊问它一句
python tools/fake_onebot.py --group 123456789     # 群里 @ 它

python tools/fake_onebot.py --listen              # 常驻：终端里打字当说话
```

## 语音这回事（要说清楚）

拆成两个方向，因为**能力不对等**：

**出（小糖人 → 你）**：✅ 完整可用。走大脑的 TTS，`voice.auto` 三档：

| 值 | 行为 |
|---|---|
| `off` | 永远打字 |
| `mirror`（**默认**） | 你先发语音，我也回语音（不主动开口吓人） |
| `always` | 每次都回语音（超过 `max_chars` 自动改打字） |

`max_per_minute` 给语音单独限流，免得连着刷一堆语音条。

**入（你 → 小糖人）**：⚠ **本地没有语音识别**。本体的语音模块只有 TTS（说），
没有 ASR（听）—— B站那个项目不涉及，DST 那边也一样。

所以走的是大老大拍板的那条路：**用 QQ 自己的转写**（手机上那个「转文字」）。
`asr.engine` 的**默认值就是 `qq`**，优先使用网关转写；网关没有返回转写时默认由 `asr.fallback=openai` 走兼容转写接口（音频请求可能计费）。设 `fallback=none` 才完全不做外部兜底。

**四级降级，每级都留痕，绝不假装听懂**：

| 顺序 | 做法 | 花钱 |
|---|---|---|
| ① | 消息段里直接给了 `record.text`（网关顺手挂上的转写） | 不花 |
| ② | 段里没有 → **拿 `message_id` 回头问网关**（SnowLuma 的 `fetch_ptt_text`，别名 `get_ptt_text` / `get_record_text`） | 不花 |
| ③ | `asr.engine=openai` → 下载语音走外部 `/audio/transcriptions`（whisper 这类） | **要花，音频过上游** |
| ④ | 都没有 → 返回空串，按 `[语音]` 记下 | — |

| `asr.engine` | 行为 |
|---|---|
| `qq`（**默认**） | 走 ①②，都没有就按 `[语音]` 记下 |
| `openai` | 走 ①②③，还拿不到才认输 |
| `none` | 不识别，一律记 `[语音]` |

③ 的两个字段（`asr.base_url` / `asr.api_key`）留空就用大脑给本功能配的那份中转。

> ⚠ **中转不一定有 whisper。** vsllm（New API）实测 `whisper-1` 是
> `503 No available channel for model whisper-1` —— 它 84 个模型里没有任何 ASR。
> 所以在 vsllm 上选 `openai` 是**没有兜底的**，只是白等一次。要在本机听语音，
> 得另找一家带 whisper 的中转，或者本地起个 faster-whisper。

### 怎么确认你的网关给不给转写（30 秒验一下）

`qq` 这条路能不能走通，**取决于网关**。装完语音先验一次，别等聊起来了才发现没听懂：
让别人给你发一条**语音**，然后看桥的日志：

| 日志里看到 | 含义 | 你要做的 |
|---|---|---|
| `🎧 QQ 转写：今晚吃什么` | 转写到手了（① 段里就有） | 什么都不用做 |
| `🎧 QQ 转写（问网关要的）：今晚吃什么` | 转写到手了（② 回头问的） | 什么都不用做 |
| `ℹ 收到语音，网关没给转写，也没开外部识别` | ①② 都没结果 | 换 `openai` 兜一层，或接受 `[语音]` |

**换网关不用改桥的代码** —— 哪个给转写就用哪个。

#### 工具中心统一管理（2026-10-21）

普通 QQ 回复（含群聊多角色）通过后端工具中心执行工具，不再使用 QQ 桥旧的
`tools.*` / `owner.tools` 配置。请在工具中心选择能力、允许目录、主人身份，
开启总开关及「QQ 桥」入口；消息发送者还必须匹配 QQ 桥的 `owner.qq`。
网页搜索无需开放本地文件能力。执行预算、沙盒边界和运行记录均复用工具中心。
普通闲聊不增加工具模型请求；搜索、文件、提醒、记账等请求会进入工具处理。
多角色共用一次结果，再由现有回复流程组织气泡，不为每个角色重复搜索。
旧版独立工具函数仅保留兼容用途，不用于正常 QQ 会话。

#### 本地语音兜底（2026-10-21）

设置 `asr.engine=local` 可直接复用后端桌宠的 Paraformer；`qq` 模式配合
`asr.fallback=local` 则先尝试 QQ 转写。无需云端 ASR 密钥。
后端需安装 `local-voice` 可选依赖与 Paraformer 模型。QQ 原生 SILK 由 `pilk`
解码，再交给本地识别；普通 ffmpeg 通常无法直接解码 SILK。
上传及解码临时文件在完成后清理，识别文字会进入聊天记录。

#### SnowLuma 实测：`fetch_ptt_text` 在**旧语音**上拿不到（2026-10-14 现场）

`get_friend_msg_history` 翻出一条几小时前的真语音，直接问 SnowLuma HTTP 3000：

```
fetch_ptt_text {"message_id": -383226619}
→ {"status":"failed","retcode":100,"wording":"语音转文字超时（未收到结果推送）"}   # 等满 20s
```

它自己 `SnowLuma/logs/snowluma-*.log` 里也是同一句。读源码（`index.mjs` 的
`ptt-trans-waiter.ts` / `media-actions.ts`）能确认它**动作是认真的**：
`waitPttTransText(key, 2e4)` 挂一个 20 秒的 waiter，同时把请求发给 QQ，
等 QQ 推 `handlePttTransResult` 回来 `deliverPttTransText`。

**没等到推送**，两种可能，日志还分不出来：

1. QQ 侧压根没做这条语音的转写 —— 手机上「转文字」是**点一下才触发**的，
   没点过的语音服务器就没有结果可推；
2. 这条**太旧了**，QQ 不给历史语音转写（SnowLuma 自己也提示「消息不存在或已被撤回」这类）。

**所以别拿旧语音下结论。** 让人**当场发一条新语音**，再对照上面那张日志表看 ——
若那时能出现 `🎧 QQ 转写（问网关要的）`，说明只是「旧语音不行」，日常聊天是好的；
若新的也超时，才说明 SnowLuma + 这个号真的拿不到，那就只剩 ③（外部 whisper）。

## 偶尔主动来找大老大

QQ 桥设置新增「主动联系」。默认关闭；填好 `owner.qq` 后开启「偶尔主动来找大老大」，选择用于联系的账号序号（从 0 开始）。默认私聊绑定的主人；指定群 @ 与空间须在「自主活动」里单独配置。按当前所选角色发言；「群聊」模式每轮只由一位在场角色起头，共用额度。

默认北京时间 10:00–23:00，每隔 90–180 分钟随机产生一次机会，由模型决定说一句、申请看看 B 站候选，或者安静跳过。刚聊完 30 分钟内不主动联系；每天最多 3 轮，你未回复时当天不连续追发。短句共 1–3 个气泡、最多 180 字，可以配一张已知表情，不改变普通聊天的回复长度设置。

给主人私聊发「今天别打扰我」或 `/proactive pause` 暂停当天主动联系；「可以来找我了」或 `/proactive resume` 恢复。前端关闭总开关长期停止。账号或用户身份变化后停止主动发送；关闭开关、等一次设置同步（约 30 秒）后重新开启，才能重新绑定。

B 站分享复用 `features/bilibili-scout/scout/qq_candidates.py` 的独立只读适配器和现有口味评分、当前「想看的／别给我看的」。只取综合热门里的少量公开标题/简介，选不到合适内容就不分享，不保证每次都找到。最多每天分享一个官方 BV 链接，不下载、不发送视频文件，不声称已经看完。分享过的 BV 号持久化去重。

适配器经过现有工具运行时的只读白名单与主人身份校验；固定子进程模块，无模型可控 argv、路径或 URL，不继承 API 密钥环境变量。网络固定 B 站公开接口，禁用代理及重定向、限响应大小与超时，超时终止子进程。QQ 发送仍由可信发送器执行，不放入只读工具注册表。它不是运行不可信代码的系统沙箱。

自主活动现在统一累计输入＋输出 token，默认单次 12,000、每天 24,000；常规输出上限 600，顾问 400，最多 6 次模型调用/10 分钟作为额外防卡死。预算与草稿在本体 SQLite 持久化；桥的频率、绑定和发布状态在 `data/proactive.json`。重启不清账、不补发过期问候。计划、跳过和随机触发不会伪造为用户发言；未知发送结果不自动重发。

已支持白名单 B 站读取、需求文档草稿与一次计量顾问请教；剩余预算不足不再调用，未知用量当天停止。操作系统级隔离、任意代码执行与主动戳一戳仍未开放。详见本体 `docs/qq-autonomous-exploration.md`。

## 图片 / 视频 / 表情包

连续输入收集、多气泡发送、表情含义标注与语义选图已实现。官方依据、实现范围及主动联系方案见
[聊天体验排查与方案](CHAT-EXPERIENCE-PLAN.md)。

默认停顿 2 秒后合并理解连续文字与图片，一轮最长收集 10 秒。模型一次生成有序动作，再按约 1.2 秒间隔发送，最多 4 个气泡，可文字 → 表情 → 文字。当前仍需等整轮生成完成；尚未接实时 token 流。续发会作废旧计划未发部分，已经发出的内容如实保存。

**收进来**（对方发的）：

- 图片、表情包 → `/api/qq-bridge/attachments` → 附件管道（**按内容签名去重**，群里反复发同一个表情只存一份）
- 视频 → 存原文件 + 请大脑抽 ≤4 帧（默认）走视觉路 → 小糖人真的看得到画面
- 抽帧或转码失败是**正常路径**（QQ 里转发的视频经常超 15 秒 / 50MB）：
  退化成「[视频]」占位，不报错、不影响回话

**发出去**（小糖人发的）：

- **表情包**：库就是**大脑的附件库**（前端显示、删消息级联、存储管理全跟着走），
  这里只留一份索引（一串 `/api/files/…` 引用，见 `sticker.library`）——
  **不另存一份副本**，否则删了消息表情还在、存储管理也算不到，两本账。
  - 默认 `sticker.reply_chance = 0`（**不主动发**，免得像刷屏机器人）；
    想让它偶尔来一张，调成 `0.1` 之类 —— 大老大喜欢小糖人的表情包，这个值随便往上调。
  - 被明确点名（「发表情包」）时直接提供真实候选，普通聊天则按概率提供；由回复模型决定是否适用，没有合适图片就不发。
  - `sticker.auto_collect` 开着的话，它会把群里收到的表情**学下来**存进库
    （最多留 300 张）。想直接给它一批，在小窝前端「表情包库」里加 / 删。
  - `sticker.auto_describe` 开启后，用 QQ 桥配置的视觉模型对每份原图自动标注一次；动图取首、中、末关键帧。只描述外形、动作和 0–3 个固定情绪标签，不猜角色名。失败不反复重试。
  - 启动时最多识别 3 张旧图；更多可在「表情的含义与情绪」中点击识别，或手写修订。不使用 embedding；小图库直接提供描述和标签，大图库先以文字重合筛到 12 张，再由同一回复模型选编号，每轮至多一张。无情绪标签的图不参与发送。
  - 识别会将少量关键帧送到配置的视觉服务；原图仍只存本体。标签在派生表 `qq_sticker_catalog`，不调用画廊旧版“记住图片/视频”写入长期记忆。
- **图片 / 视频**：`data/outbox/` 是**出件箱** —— 往里面丢图片或视频，
  下一轮有效回话时带出去，确认发送后移到 `data/outbox/sent/`，并记录实际附件。发送失败保留原文件。
  （这就是「小糖人也能发图片视频」的口子；以后别的功能想让它在 QQ 里发东西，也走这里。）

## 同步进小窝（这两件事是分开的）

| | 说明 |
|---|---|
| **同步** | 白名单里的会话**一律**写进前端聊天记录：群聊 → `group`，私聊 → `single-<这个号演的人>`。哪怕这条没 @ 我、哪怕这个会话设了静音 —— **同步是记录，不是打扰**。 |
| **开口** | 群里默认**要 @ 才回**（`allow.require_mention_in_group`）；私聊直接回；`modes.dm/group = "silent"` 时只同步不开口。 |

入站原文与附件先持久化，出站仅在 QQ 确认成功后记录实际文字/图片。生成计划、失败内容、被打断的尾段均不保存成助手已说过的话。

**记忆按当前本体方案**：原文及附件 → 01 归档 → 清洗 → 每日事件草稿 → 人工审核并启用 → 普通提示词注入。身份和在场成员筛选与网页一致。`memory.enabled` 只控制自动每日整理，不关闭原文保存。

旧 `memory.isolate/window/idle_seconds` 和 `sync.to_frontend` 在现代会话入口已不生效，前端移除相应开关；旧兼容方法保留，但正常运行不调用旧攒轮次提炼。`sync.persona_id` 留空跟随当前用户身份，填写已有身份 ID 则固定归属。

桥将待保存入站事件、已发送但尚未入库的回执、待整理会话写入 `data/conversation-delivery-<账号摘要>.json`。后端恢复后只重试落库，不重发 QQ。身份服务掉线期间的原始事件也保留，恢复时归档而不迟到插话。平台已经发送但确认尚未返回时被强制终止，仍存在无法判定是否送达的窗口，无法承诺跨 QQ 平台的严格一次性发送。

## 本地小工具（大老大说「可以碰，只要别搞坏东西」）

默认**关**。开了之后小糖人可以在**划定的目录里**列目录 / 读文本 / 找文件 / 看看自己的边界，
但每次调用都要过**三道闸**（全在本进程里，模型看不见实现）：

1. **谁能触发** —— 默认只有大老大的消息。群里别人说「让小糖人删个文件」不算，那是提示注入不是授权。
2. **白名单动作** —— 登记表是**代码常量**（`tools.ACTIONS`），配置只能从里面挑名字，**加不进新动作**。
3. **沙箱路径** —— `resolve()` 之后的真实路径必须仍在根里；`..` / 符号链接 / 绝对路径直接指外面，一律拒绝。

另有一条**写死在代码里、配置改不动**的兜底：删除 / 关机 / 格式化 / 改注册表 / 联网下载 / 起别的程序，
永远拒绝。被拒时会**如实告诉模型**「做不了」，不换个说法硬编。

模型那侧靠大脑的 `POST /api/nest/tool-turn`（§9.6.6）：**大脑只透传模型的调用决定，一个动作都不执行** ——
执行永远发生在这个进程里（只有它知道沙箱在哪）。

> 参考项目是靠「不给模型工具」（closed-agent 模式）来保险的。我们换成「给工具 + 硬边界」：
> 能做的事更多，而边界是代码写死的，不靠模型自觉。

## 改 QQ 个人资料（已验证）

QQ 号自己的昵称 / 签名 / 性别 / 头像，走网关的 OneBot 动作就能改 —— **桥不存这些，也不替小糖人
决定写什么**，这里记的是「怎么改」和「哪几个字段真能改」。

| 动作 | 参数 | 本机实测 |
|---|---|---|
| `set_self_longnick` | `longNick`（**严格 string**） | ✅ 成功。签名立刻生效 |
| `set_qq_profile` | `nickname` / `personal_note` / `sex`（0 未知 1 男 2 女） | ✅ 只传单个字段也成功 |
| `set_qq_avatar` | `file`（图片，路径或 URL） | 未测 |
| `set_diy_online_status` | `face_id` / `wording` / `face_type` | 未测 |

已改的：553350415（芳月诗音）签名 → `小糖人之家的大姐头 · 烤小饼干、泡热可可`。

**两个坑，都踩过**：

1. **`personal_note` 和签名是同一个东西** —— 一起传会 `OIDB error 999 ... set longnick Fail`。
   所以：**要改签名就用 `set_self_longnick`，别混在 `set_qq_profile` 里**；
   `set_qq_profile` 只用来改昵称和性别（本机验证：单独传能成）。
2. **中文要从文件发** —— Windows 终端直接 `curl -d '{"longNick":"中文"}'` 会被 GBK 折成乱码存进去
   （看回读的 `long_nick` 是一串 `С`）。用 `--data-binary @payload.json`、
   `Content-Type: application/json; charset=utf-8`，payload 文件按 utf-8 写。桥里发中文本来就走
   `json.dumps(..., ensure_ascii=False)` + utf-8 编码，不会有这问题。

回读用 `get_stranger_info`（带自己的 `user_id`）—— `get_profile` / `get_self_longnick` 这类
**SnowLuma 没有**（回 `1404 unknown action`）。这里能读到 `nickname` / `long_nick` / `sex`。

## 安全边界（有意为之，别改松）

- **白名单为空 = 谁都不理**。不做「默认全接」。
- 群里默认要 @。不 @ 只同步，不插嘴。
- **`access_token` 留空 = 不校验**：任何能连到本机那个端口的程序都能指挥小糖人发消息。
  本机自用一般没事（还挡着「只允许本机回环连大脑」这条）；装了别的软件、或端口对局域网开放时，
  **强烈建议设一个**，网关那边填一样的。设了之后对不上就是 401。
- **只允许本机回环 HTTP 连大脑**（大脑没有鉴权，绝不能指向公网）。
- 密钥只在内存里过一遍，不落盘、不打日志。
- 下载的 URL 只认 `http` / `https` / `file`，且有体积上限。
- 临时文件（下载的图、合成的语音）用完就删；语音临时文件一天后清。
- **本地小工具默认关**，开了也只在划定目录里、只跑代码里写死的那几个只读动作（见上一节）。

## 测试
